# Enforcement is a capability ladder, not a promise

A portable specification cannot promise identical enforcement across harnesses. Pi can block a tool call from an extension; Claude Code can block one from a `PreToolUse` hook; a harness with neither can only advise the model and check the result in CI. Treating those as the same thing is how a gate becomes a suggestion: the document says "no writes without a stake", the harness cannot enforce it, and nothing tells the gardener that the gate was not real.

We therefore name four enforcement levels and require every adapter to declare which it provides. **Advisory** is instructions and skills only; it works everywhere and suppresses drift, but it cannot stop a determined leaf. **Hooked** is a pre-tool check that calls the kernel and can block; pi and Claude Code provide it. **Orchestrated** is the kernel owning dispatch and running leaves in an isolated worktree or container with `.garden/` read-only; it is the strongest tier. **Groundskeeper** is CI, git hooks, and bots; it is the only tier that is both portable and proof of soundness.

A repo declares the level it requires in `garden.toml`. `garden doctor` reports the level the current harness actually provides, and refuses to pretend. Where possible, gates are file-based and actor-agnostic — an active lease names the stake and the paths a leaf may touch — so enforcement does not depend on knowing which agent made the call. A hook is a guardrail, not a sandbox: if a leaf has the same OS permissions as the gardener, it can bypass the hook. The security boundary is isolation, not interception.

**Consequences:** No silent downgrade. A repo on an unhooked harness runs at advisory level and says so. CI is the portable proof of soundness, so the groundskeeper tier is mandatory for every adapter. Role restrictions are enforced by tool exposure — a leaf never gets the harvest tool — rather than by trusting the leaf to decline. The strongest guarantee requires orchestrated isolation, which is heavier to adopt and therefore a later tier, not the entry fee. The framework must document, per adapter, which gates are blocking and which are advisory.

**Considered options:** claim identical enforcement everywhere (rejected: false, and it trains gardeners to trust gates that do not exist); support only hooked harnesses (rejected: excludes most of the ecosystem and defeats portability); rely on prompt-level gates alone (rejected: self-certification is exactly what the framework exists to prevent); require sandbox isolation for all work (rejected: correct but too heavy for adoption; kept as the orchestrated tier); let each adapter define its own gate semantics (rejected: the semantics must be shared or the vocabulary is not).
